# 耳机使用记录器（Headphone Logger）设计文档

- 日期：2026-08-14
- 状态：设计稿，待用户审阅
- 工作目录：`D:\Claudeworkspace\headphone-logger`

## 一、目标与价值

一个 Windows 常驻后台的**耳机使用记录小软件**，解决两个问题：

1. **时间记账**：知道自己一天、一周、一月到底戴了多久耳机。
2. **场景分配**：这些时间里，多少花在音乐、视频、游戏、网课、会议、编程……判断自己的时间分配。

**核心用户洞察**：用户耳机基本**一直插着**，所以「插入→拔出」不是有意义的分段边界。真正有意义的分段是**场景切换**（听着歌打游戏这种并发场景也要同时记录）。

## 二、技术栈

| 项 | 选择 | 理由 |
|---|---|---|
| 语言/框架 | C# .NET 10 + WinForms | 本机已有 .NET 10 SDK；Windows 原生方案最稳 |
| 音频设备插拔监听 | NAudio `MMDeviceEnumerator` + `IMMNotificationClient` | 官方能力，原生支持 |
| 发声进程枚举 | Core Audio `IAudioSessionEnumerator` | 实现「并发场景」的技术依据 |
| 存储 | SQLite（`Microsoft.Data.Sqlite`） | 单文件本地库，零配置 |
| 托盘 | WinForms `NotifyIcon` | 最正统 |
| 统计图表 | WebView2 内嵌 + ECharts | 复用用户熟的图表技术，好看 |
| 开机自启 | 注册表 `Run` 键 | 静默常驻，可关闭 |

## 三、整体架构

四个独立模块，各司其职、接口清晰、可独立测试：

```
┌─────────────────────────── Windows 桌面（托盘常驻）───────────────────────────┐
│                                                                             │
│  ┌──────────────┐  插拔事件    ┌──────────────┐  增删改查   ┌────────────┐   │
│  │ AudioWatcher │ ──────────▶ │ SessionManager│ ─────────▶ │  SQLite     │   │
│  │  (NAudio监听) │            │ (会话管理)    │            │  (本地存储)  │   │
│  └──────────────┘             └──────┬───────┘            └────────────┘   │
│           触发气泡                   │ 写记录                                 │
│       ┌───────────┐         ┌────────▼────────┐                            │
│       │ 气泡确认窗 │◀────────│ ForegroundScanner│（抓前台进程→预填场景）         │
│       │ (预填场景) │         └─────────────────┘                            │
│       └───────────┘                                                        │
│  ┌───────────────────────────────────────────────┐                         │
│  │  统计窗口：场景占比饼图 / 每日时长柱状 / 时段热力图│                          │
│  │  （WebView2 内嵌 ECharts）                      │                          │
│  └───────────────────────────────────────────────┘                         │
└─────────────────────────────────────────────────────────────────────────────┘
```

- **AudioWatcher**：只负责监听并上报「耳机插入/拔出」与「当前发声进程集合」。对外暴露 `IAudioDeviceMonitor` 接口（NAudio 为实现之一），使 SessionManager 可脱离硬件测试。
- **SessionManager**：会话状态机（空闲→使用中→结束），落地数据库；负责所有兜底逻辑。
- **ForegroundScanner**：取出前台进程名 + 窗口标题，供场景预填。
- **统计窗口**：只读展示，从数据库聚合计算，含明细修正入口。

## 四、数据模型（SQLite）

### `sessions`（一次插拔 = 一个会话）
| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | INTEGER PK | 自增主键 |
| `start_time` | TEXT | 插入时刻（ISO8601 UTC） |
| `end_time` | TEXT | 拔出时刻，可空（悬挂会话） |
| `duration_sec` | INTEGER | 总时长，结束或补记时写入 |

### `segments`（会话内的场景段）
| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | INTEGER PK | 自增主键 |
| `session_id` | INTEGER FK | 所属会话 |
| `start_time` | TEXT | 段开始 |
| `end_time` | TEXT | 段结束，可空（进行中） |
| `duration_sec` | INTEGER | 段时长 |
| `app_name` | TEXT | 主场景前台进程名（预填依据） |
| `window_title` | TEXT | 前台窗口标题（辅助判断） |
| `confirmed` | INTEGER | 0/1，是否经用户确认 |
| `note` | TEXT | 备注，可空 |

### `segment_scenes`（段 × 场景，多对多）
| 字段 | 类型 | 说明 |
|---|---|---|
| `segment_id` | INTEGER FK | 所属段 |
| `scene` | TEXT | 场景标签 |

**并发场景模型**：一个段可带多个场景标签。听歌打游戏 1 小时 → `segments` 一条 3600 秒，`segment_scenes` 两行（游戏 + 音乐）。

### `scene_rules`（进程名/标题关键词 → 场景 映射规则）
| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | INTEGER PK | 自增主键 |
| `app_pattern` | TEXT | 进程名模式（如 `chrome.exe`） |
| `title_pattern` | TEXT | 窗口标题关键词（如 `bilibili`），可空 |
| `scene` | TEXT | 映射到的场景 |
| `enabled` | INTEGER | 0/1 |

初始规则示例：
```
chrome.exe + "哔哩哔哩/bilibili" → 视频
chrome.exe + "YouTube"            → 视频
chrome.exe + "网易云音乐"          → 音乐
Code.exe / idea64.exe             → 编程
WeChat / 腾讯会议 / Zoom           → 会议
steam.exe / LeagueClient.exe      → 游戏
学习通 / 智慧树                      → 网课
默认（无匹配）                      → 其他
```

场景枚举：`音乐 / 视频 / 游戏 / 网课 / 会议 / 编程 / 其他 / 未标注`。

## 五、核心交互流程

### 场景切换（主触发点）
**触发判定**：前台进程/窗口发生变化，且按规则映射出的主场景与当前段不同 → 触发一次切换。同一场景内的窗口切换（如 Chrome 内 bilibili→YouTube）不触发。

```
前台应用跨场景切换（网易云→bilibili）
   │
   ▼
气泡确认：「切到「视频」了？检测到音乐播放中」
   │
   ├─ [✓ 是] → 当前段结束，开新段（视频），若检测到音乐发声则同时打「音乐」标签
   └─ [✕ 让我改] → 弹出下拉手动选场景（改主场景；已检测到的并发发声进程仍自动附为标签）
```

并发场景：当主场景之外有其他进程正在发声（`IAudioSessionEnumerator`），自动附加为并发标签。**去重规则**：并发标签自动排除与主场景相同的发声进程——前台就是网易云时，主场景已含「音乐」，不再重复附加。

### 会话边界
```
耳机插入 ──▶ SessionManager 新建 session（记 start_time）
   │
   ▼ （静默后台监听，不打扰）
   │
耳机拔出 ──▶ 结束 session（记 end_time + duration_sec）
```

**设计要点**：
1. 插入静默、场景切换才问——插上耳机不打扰。
2. 气泡默认聚焦确认，1 秒完成；忽略仍落库但 `confirmed=0`。
3. 气泡存在期间，若 5 分钟无操作，按自动检测值落库，标 `confirmed=0`。
4. 气泡实现：WinForms 原生 `ShowBalloonTip` 只有纯文本、无按钮，故「✓是 / ✕让我改」用**无边框 TopMost 的自定义 Form** 实现（非系统 Toast，避免依赖通知权限）。

### 边界情况兜底
| 情况 | 处理 |
|---|---|
| 插了不到 1 分钟就拔 | 视为误插，不落库（防抖动）；但若期间已产生过**已确认**的 segment，则保留该 segment |
| 气泡弹出时前台被抢 | 延迟 1 秒再抓前台 |
| 用户不在 / 忽略气泡 | 5 分钟无操作自动按预填值落库，标未确认 |
| 启动时耳机已插着 | 只记基准状态，不产生虚假会话 |
| 关机/睡眠留下悬挂会话 | 启动时把已结束的悬挂会话补 `end_time` |
| 连续拔插抖动 | 合并逻辑，不产生碎记录 |

## 六、统计窗口

托盘菜单 →「查看统计」。WebView2 内嵌 ECharts：

| 视图 | 内容 |
|---|---|
| 总览 | 今日/本周/本月时长，环比卡片 |
| 场景分配 | 饼图 + 各场景时长表 |
| 每日时长 | 柱状图，最近 30 天 |
| 时段分布 | 热力图：一周七天 × 24 小时 |
| 明细列表 | 按日/场景筛选，每条 segment 可点开补标/改场景/加备注 |

> **改数据链路**：统计窗是 WebView2 内嵌 HTML，明细修正需经双向桥接——前端 `window.chrome.webview.postMessage` → C# `WebMessageReceived` 写 SQLite → 回传刷新。这条桥接是数据流的一部分，实现计划需单独列任务。

**统计口径（重叠如实呈现）**：一个段时长同时计入每个场景。60 分钟 [游戏, 音乐] = 游戏 60 分钟 + 音乐 60 分钟。场景分配饼图各场景之和**可以大于**总使用时长。图上标注「游戏 2.5h（其中 1.2h 同时在听歌）」显式展示重叠量。

**时区口径**：所有时间**存储用 UTC**（可排序、免歧义），**聚合与展示一律换算本地时区后按本地日界切**。国内 UTC+8，深夜 23:00–01:00 的使用会跨 UTC 日界；若按 UTC 聚合，会把本地 08:00 前的使用算进「昨天」。故「今日/本周/本月」一律按本地时区日界聚合。

## 七、错误处理

| 风险 | 兜底 |
|---|---|
| 数据库损坏 | 启动完整性检查，损坏自动改名 `.bak` 重建 |
| 插拔事件丢失（驱动/睡眠） | 启动时补悬挂会话 `end_time` |
| 气泡被忽略 | 按自动检测值落库，标 `confirmed=0` |
| 规则匹配失败 | 兜底「其他」，绝不崩溃 |
| 单实例冲突 | Mutex 保证单实例，防双写 |

## 八、测试策略

- **单元测试**：场景规则匹配引擎、会话状态机、统计聚合函数（含「重叠计入」逻辑）——纯逻辑，不依赖硬件。
- **接口测试**：SessionManager 依赖 `IAudioDeviceMonitor` 抽象，测试用假实现注入假插拔/假发声进程，验证状态机流转。
- **不测硬件**：真实耳机插拔靠手动冒烟验证。
